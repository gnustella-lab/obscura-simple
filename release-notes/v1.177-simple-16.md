# Obscura Simple 1.177-16

This release separates the unofficial community client from official Obscura Linux packages and adds a Flatpak GUI bundle.

## Downloads

- `obscura-simple_1.177-16_amd64.deb`: host service, CLI and native GUI. Targets Ubuntu 24.04-compatible systems.
- `obscura-simple_1.177-16_x86_64.flatpak`: sandboxed GUI using GNOME Platform 50.
- `SHA256SUMS`: checksums for both packages.

Download both packages and the checksum file into one directory, then verify:

```bash
sha256sum -c SHA256SUMS
```

## Important: the Flatpak requires a host service

The Flatpak is the interface, not a standalone privileged VPN backend. Install the matching `obscura-simple 1.177-16` host package first. The official Alpha service is separate and does not satisfy this dependency.

```bash
sudo apt install ./obscura-simple_1.177-16_amd64.deb
sudo obscura-simple add-operator "$USER"
flatpak install --user ./obscura-simple_1.177-16_x86_64.flatpak
flatpak run io.github.gnustella_lab.obscura_simple
```

The installer does not start or enable either VPN service. When deliberately choosing Simple, stop any other VPN backend yourself before starting `obscura-simple.service`. Only one backend can own networking at a time. Do not enable both at boot.

Start the host service before opening the Flatpak, and reopen the Flatpak after any host-service restart because its file-mounted sockets may otherwise retain the old inode. Host permission setup, complete diagnostic archives and desktop autostart configuration remain host-side operations.

GNOME Platform 50 is downloaded separately from Flathub if needed. The bundle does not contain the runtime and does not configure an automatic application-update repository.

## Changes

- Dedicated executable, service, operator-group, IPC, state and desktop-integration identities.
- Separate GTK/WebKit user storage and autostart entry, without automatically migrating official credentials or settings.
- Shared backend lock retained before firewall/TUN/DNS initialization to prevent concurrent VPN backends.
- Passive package installation and removal scripts that do not manage the official service.
- Explicit unofficial-client branding and separate community/service support links.
- Flatpak-specific setup guidance and unsupported host controls hidden and blocked in the UI.
- Flatpak permissions limited to display, network, GPU/IPC, the two Simple sockets, tray integration and filtered systemd D-Bus access. No full-home access or arbitrary host-command permission.

The Flatpak contains the same source-built native GUI executable as the .deb, verified against its GNOME runtime. It is not a launcher that executes the GUI on the host.

## Verification and limits

- 17 JavaScript regression tests passed.
- 21 Rust unit tests passed; 3 privileged kernel/network integration tests remained explicitly ignored.
- Real .deb payload checked against installed official packages, with no overlapping files.
- APT simulation adds only Simple and removes no packages.
- The Flatpak was installed in an isolated user installation and launched with a real GTK/WebKit window. Its D-Bus identity and sandbox permissions were checked.
- A local Unix-socket transport fixture confirmed that read-only socket mounts work and preserve the host peer UID. This was not a live VPN connection test.
- Official binaries and package integrity remained unchanged, and the official VPN service remained running.

No live VPN handover, reboot or leak test was performed for this release. Boot kill-switch protection requires explicitly configuring the host service to start at boot; it is disabled by default. Legacy `1.177-15` purge scripts predate isolation and can affect the official service, so review them before purging old residual configuration. Do not delete shared official state as a migration shortcut.

The existing project license and notices are preserved. This is an independent community client, not an official Obscura release.
