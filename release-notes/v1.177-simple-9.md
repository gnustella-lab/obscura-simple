# Obscura Simple UI 1.177-9

The Linux kill switch is now a regular setting in Simple UI, with the experimental label removed.

## Changes

- Apply the saved kill switch policy before network preparation at boot. The service announces readiness only after the kernel acknowledges the blocking rules.
- Keep protection active while retrying an unreadable or invalid configuration, and resume initialization after it is repaired.
- Apply firewall rules before DNS setup so a DNS failure cannot prevent protection.
- Display the acknowledged firewall state separately from the saved preference.
- Preserve blocking rules across service crashes and restarts.
- Update the Debian package and both executable version strings to `1.177-9`.

## Validation

The kill switch changes passed 18 Rust unit tests and 3 isolated nftables/TUN tests. Package-level validation used Ubuntu 24.04 amd64, kernel `6.8.0-138-generic`, systemd `255.4-1ubuntu8.17`, and a real VPN connection in a KVM guest.

Two protected boots captured zero unmarked DNS, UDP or TCP packets outside the VPN. A disabled-kill-switch boot correctly allowed traffic. Tunnel loss/reconnection, network switching, deep suspend/resume, service crash/restart, and invalid-configuration recovery also passed without observed leaks. This validation does not cover every distribution or physical network/suspend implementation.

See [the boot protection report](https://github.com/gnustella-lab/obscura-simple/blob/v1.177-simple-9/KILL_SWITCH_BOOT_FIX_REPORT.md) for the detailed results. The report identifies the pre-release test build; release asset hashes are provided in `SHA256SUMS`.

## Installation or upgrade

Download `obscura-simple_1.177-9_amd64.deb` and `SHA256SUMS` from this release, then run:

```sh
sha256sum -c SHA256SUMS
sudo apt install ./obscura-simple_1.177-9_amd64.deb
```

The package upgrades the existing `obscura-simple` installation and restarts its active service. Package architecture: **amd64**. No account credentials are included.
